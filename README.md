# Portfolio

اپ اندروید Flutter با رابط فارسی و RTL برای مشاهدهٔ یکپارچهٔ دارایی مفید و آی‌پاسارگاد، تفکیک موجودی بین سبدهای محلی، دیده‌بان، قیمت‌های عمومی TGJU، اشتراک LAN و خروجی Markdown.

## آنچه در این نسخه پیاده شده است

- معماری feature-first با `data / domain / presentation`، مدیریت state با Cubit، خروجی Repositoryها با `Future<Either<Failure, T>>` و DI با `get_it + injectable`.
- ورود مستقیم مفید بدون مرورگر داخلی: اپ با HTTP قرارداد OIDC Authorization Code + PKCE مشاهده‌شده را اجرا می‌کند، صفحهٔ Login را برای anti-forgery token می‌گیرد، `POST /Login` را با نام کاربری/رمز می‌فرستد، callback را دنبال می‌کند و کد را با `POST /connect/token` به access token تبدیل می‌کند.
- نگهداری access token، شناسهٔ مشتق‌شدهٔ حساب و نام کاربری/رمز مفید در `flutter_secure_storage`. در اجرای بعدی اپ، `local_auth` اثر انگشت را درخواست می‌کند؛ اگر token هنوز معتبر باشد همان نشست باز می‌شود و اگر منقضی شده باشد پس از تأیید اثر انگشت، Login مستقیم با credential ذخیره‌شده تکرار می‌شود.
- دریافت موجودی جاری از `/assetmodule/api/performance`، قدرت خرید گزارش‌شده از `/easy/api/money` و قیمت نمادها از `/symbols/api/marketdata`.
- بخش «افزودن اکانت» بعد از ورود مفید؛ در این فاز فقط آی‌پاسارگاد قابل افزودن است و معماری برای Providerهای بعدی آماده است.
- ورود آی‌پاسارگاد با قرارداد واقعی کپچا + `POST /Account/Login` استخراج‌شده از HAR؛ token نشست در Secure Storage نگهداری می‌شود و در APIهای بعدی به‌صورت cookie `otauth-FU` ارسال می‌شود.
- یک cookie مرورگری به نام `cookiesession1` در capture از قبل وجود داشت ولی محل ایجادش ثبت نشده است؛ بنابراین Login مستقیم آی‌پاسارگاد تا تست روی دستگاه واقعی «تأییدنشده» باقی می‌ماند.
- دریافت موجودی آی‌پاسارگاد از composition/evidence/profit-loss و تبدیل ریال به تومان در مرز data؛ وضعیت واحد باید در اولین اجرای واقعی با UI آی‌پاسارگاد تطبیق داده شود.
- هویت هر دارایی بر اساس `accountId + symbolIsin` است؛ بنابراین اگر «ریتون» هم در مفید و هم در آی‌پاسارگاد باشد، دو کارت جدا با برچسب منبع نمایش داده می‌شود و تخصیص‌های محلی با هم قاطی نمی‌شوند.
- قیمت برآورد فروش با اولویت بهترین سفارش خرید؛ در نبود آن، آخرین معامله و سپس قیمت پایانی با برچسب صریح استفاده می‌شود.
- نمایش حجم بهترین خریدار و هشدار در صورتی که از تعداد سهم نمایش‌داده‌شده کمتر باشد.
- ساخت، تغییر نام و حذف سبدهای محلی؛ تخصیص تعداد هر نماد بین سبدها؛ جلوگیری از تخصیص منفی یا بیش از موجودی؛ نمایش بخش تخصیص‌نیافته.
- داده‌های سبد محلی به حساب اصلی مفید scope می‌شوند و تخصیص هر دارایی با `holdingKey` حساب‌محور ذخیره می‌شود تا نماد یکسان در دو Provider با هم مخلوط نشود.
- فهرست حساب‌های اضافه نیز به حساب اصلی مفید scope می‌شود تا ورود با یک حساب مفید دیگر، اتصال‌های آی‌پاسارگاد کاربر قبلی را وارد نمای جدید نکند.
- حالت نمایش ارزش جاری به تومان یا «واحد معادل عیار» با ISIN عمومی `IRTKMOFD0001`.
- دیده‌بان محلی با جست‌وجوی فهرست نمادهای مفید، افزودن/حذف و refresh قیمت.
- snapshot عمومی TGJU برای دلار، یورو، سکه امامی، طلای ۱۸ عیار و حباب سکه. فقط دلار و طلای ۱۸ عیار، که واحد ریال آن‌ها در capture تأیید شده، در مرز data به تومان تبدیل می‌شوند؛ سایر اقلام با «واحد منبع» نمایش داده می‌شوند.
- خروجی امن Markdown از سبد انتخاب‌شده با ستون حساب/Provider؛ توکن، رمز و شناسهٔ ورود وارد خروجی نمی‌شوند.
- اشتراک‌گذاری مستقیم روی شبکهٔ محلی بدون backend: گوشی مالک یک HTTP server سبک روی پورت `8787` اجرا می‌کند، snapshot خواندنی پرتفوی را با Basic Auth می‌دهد و گوشی بیننده با آدرس LAN + یوزر/پس وصل می‌شود. یوزر/پس عمداً داخل سورس ثابت است: `viewer / portfolio123`.
- GitHub Actions برای bootstrap پروژهٔ Android، codegen، format، analyze، test و ساخت APK دیباگ.

## مرزهای عمداً رعایت‌شده

این پروژه عدد مالی حدسی را به‌عنوان سود واقعی نمایش نمی‌دهد. اتصال آی‌پاسارگاد در نسخهٔ فعلی برای موجودی و ارزش جاری است؛ تاریخچهٔ درخواست‌ها و NAV دیده شده اما semantics کامل سود تاریخی چندحسابی هنوز باید روی دادهٔ واقعی تأیید شود. گزارش سفارش موجود، وضعیت و `executedQuantity` تجمعی سفارش را می‌دهد و execution مستقل با شناسه/زمان/قیمت قطعی هر اجرا را اثبات نمی‌کند؛ بنابراین سود واقعی امروز/هفته/ماه سبدهای محلی و تخصیص خودکار تاریخی تا دریافت endpoint اجرای معاملات «دادهٔ کافی نداریم» باقی می‌ماند. همچنین `buyPowerT2` به‌عنوان «قدرت خرید گزارش‌شده» نشان داده می‌شود و با ارزش سهام جمع نمی‌شود، چون قدرت خرید الزاماً وجه نقد مالکانه نیست.

اشتراک‌گذاری این نسخه backend اختصاصی ندارد و روی LAN کار می‌کند. گوشی مالک باید اپ را باز نگه دارد و هر دو گوشی باید به یک شبکهٔ محلی دسترسی داشته باشند. برای مشاهده از اینترنت بدون قرارگرفتن در یک شبکه، هنوز به یک مسیر قابل‌دسترسی عمومی مثل backend/relay/VPN/port-forward نیاز است. حباب طلای ۱۸ عیار نیز از `coin_blubber` ساخته نمی‌شود؛ آن کلید حباب سکه امامی است.

## راه‌اندازی

این repository عمداً پوشهٔ generated Android را حمل نمی‌کند. در محیطی که Flutter stable نصب است:

```bash
./tool/bootstrap.sh
flutter run
```

اسکریپت `tool/bootstrap.sh` در صورت نبود `android/` آن را با شناسهٔ `com.mohamad72.portfolio` می‌سازد، مجوز اینترنت و biometric را اضافه می‌کند، `MainActivity` را برای `local_auth` به `FlutterFragmentActivity` تبدیل می‌کند، حداقل Android SDK را 24 می‌گذارد، cleartext HTTP را برای اتصال LAN فعال می‌کند، packageها را می‌گیرد و فایل‌های DI را تولید می‌کند.

برای verification کامل:

```bash
./tool/bootstrap.sh
dart format lib test
flutter analyze --no-fatal-infos
flutter test
flutter build apk --debug
```

جزئیات طراحی و قرارداد APIهای استخراج‌شده از captureهای کاربر در `docs/superpowers/specs/2026-09-11-portfolio-design.md` است. فایل‌های HAR خام، cookie، token و credential نباید وارد repository شوند.
